# بایگانی کانال تلگرام

[فهرست](index.md) · [English](../en/telegram.md) · **فارسی**

یک کانال تلگرام را در قالب یک گنجینه‌ی Obsidian بایگانی کنید: **برای هر پست یک یادداشت Markdown** (متن پست، متن پیاده‌شده‌ی صوت/ویدیو، خلاصه و *تقریر* اختیاری، فرادادهی کامل) به‌علاوه‌ی یک یادداشت فهرست کانال. برای کانال‌های صوتی/تصویری، فقط‌متنی و ترکیبی کار می‌کند.

## شروع سریع

```sh
# ۱. یک بار وارد شوید (برای کانال‌های عمومی می‌توانید این مرحله را رد کنید و از --web استفاده کنید)
versline telegram login

# ۲. پیش‌نمایش یک بازه‌ی زمانی (چیزی دانلود یا نوشته نمی‌شود)
versline telegram archive @channel --since 2026-03-01 --until 2026-03-31 --dry-run

# ۳. بایگانی در گنجینه‌ی خود
versline telegram archive @channel --since 2026-03-01 --until 2026-03-31 -o ~/Vault/Telegram/channel
```

تنظیمات LLM از `VERSLINE_LLM_*` / `versline init` یا گزینه‌های زیر گرفته می‌شود. پیاده‌سازی متن به یک سرویس LLM نیاز دارد؛ ffmpeg همراه برنامه است.

## دو روش اتصال

| | ورود با حساب (پیش‌فرض) | پیش‌نمایش وب (`--web`) |
| :--- | :--- | :--- |
| نیاز به `api_id`/`api_hash` و `telegram login` | بله | **خیر** |
| کانال‌ها | عمومی، خصوصی، و عضوشده با لینک دعوت | **فقط عمومی** (`@name`، `t.me/name`) |
| فایل صوتی، سند، ویدیوی حجیم | دانلود و پیاده‌سازی می‌شود | **قابل دانلود نیست**: برای پست یادداشت ساخته می‌شود و مورد در `skipped_media` با عبارت «<نوع> not downloadable» ثبت می‌شود |
| پیام صوتی، ویدیوی گرد، ویدیوی کوچک | بله | بله |
| سرعت | سریع | کندتر (فاصله‌ی ۰٫۴ ثانیه بین درخواست‌ها و عقب‌نشینی در خطای HTTP 429)؛ بازه‌ی زمانی با جست‌وجوی دودویی پیدا می‌شود |

**حالت ورود با حساب.** `api_id` و `api_hash` را از <https://my.telegram.org> بخش *API development tools* بگیرید. آن‌ها را در env بگذارید (`VERSLINE_TELEGRAM_API_ID`، `VERSLINE_TELEGRAM_API_HASH`) یا بگذارید `versline telegram login` بپرسد و ذخیره کند. ورود، شماره‌ی تلفن، کد و (در صورت فعال بودن) رمز دومرحله‌ای را می‌خواهد. تنظیم متغیرها به‌تنهایی ورود **نیست**. فایل نشست (در پوشه‌ی تنظیمات یا `VERSLINE_TELEGRAM_SESSION_PATH`) به حساب شما دسترسی می‌دهد؛ آن را محرمانه نگه دارید. `versline telegram logout` نشست را پایان می‌دهد و فایل را حذف می‌کند.

**حالت وب.** `--web` آدرس `https://t.me/s/<channel>` را می‌خواند؛ کانال خصوصی، لینک دعوت و `t.me/c/...` رد می‌شوند. کانال ناموجود یا بدون پیش‌نمایش، خطای «پیدا نشد» می‌دهد.

**پروکسی.** برای تلگرام ترتیب این است: `--telegram-proxy` ← `VERSLINE_TELEGRAM_PROXY` ← `--proxy`/`VERSLINE_LLM_PROXY`. پروتکل‌ها: `socks5`، `socks5h`، `socks4`، `http`، `https`. در `archive`، گزینه‌ی `--proxy` برای سرویس LLM است.

## `telegram login` / `logout`

```sh
versline telegram login [--proxy URL]
versline telegram logout
```

## `telegram archive`

```sh
versline telegram archive [OPTIONS] CHANNEL
```

`CHANNEL`: ‏`@name`، `name`، `https://t.me/name`، `t.me/s/name`، `https://t.me/c/<id>` (خصوصی) یا لینک دعوت کانالی که قبلاً عضوش شده‌اید (دو مورد آخر فقط در حالت ورود با حساب).

### انتخاب پست‌ها

| گزینه | توضیح | پیش‌فرض |
| :--- | :--- | :--- |
| `--since`، `--until` | ‏`YYYY-MM-DD[ HH:MM]` میلادی یا شمسی (`1404-07-01`؛ سال کمتر از ۱۷۰۰ شمسی است؛ ارقام فارسی و `/` پذیرفته می‌شود). تاریخ بدون ساعت کل روز را شامل می‌شود؛ `--until` شامل خودش است. | کل کانال |
| `--limit N` | حداکثر N پست منطبق | نامحدود |
| `--types` | فهرست جداشده با ویرگول از `audio,voice,video,video_note,photo,document,text` | همه |
| `--dry-run` | جدول پست‌های منطبق (شناسه، تاریخ، نوع، مدت، عنوان و با فیلتر فایل، فایل‌های منطبق) بدون نوشتن چیزی | خاموش |

نوع هر پست برابر نوع **اولین** رسانه‌ی آن است (آلبومی که با عکس شروع شود = `photo`)؛ بدون رسانه = `text`. فقط voice، audio، video و video_note پیاده‌سازی می‌شوند؛ بقیه فقط متن پست و فراداده می‌گیرند.

### فیلتر فایل‌ها

اسناد را بر اساس پسوند و نام (یا متن پست) انتخاب کنید. هم در آرشیو معمولی کار می‌کند (با `--keep-media` فقط فایل‌های منطبق دانلود می‌شوند) و هم در حالت `--files-only`.

| گزینه | توضیح | پیش‌فرض |
| :--- | :--- | :--- |
| `--ext` | فهرست پسوندها با ویرگول، مثلاً `pdf,docx`؛ ‏`word` = ‏`doc,docx`. از نام فایل و در نبودش از نوع mime گرفته می‌شود | همه |
| `--match REGEX` | فایل‌هایی که با **حداقل یکی** از الگوها جور باشند نگه داشته می‌شوند (تکرارپذیر) | همه |
| `--exclude REGEX` | فایل‌هایی که با **هر** الگو جور باشند حذف می‌شوند (تکرارپذیر)؛ بر `--match` برتری دارد | هیچ |
| `--match-in` | الگوها روی چه چیزی امتحان شوند: `name` (نام فایل)، `caption` (متن پست) یا `any` (هر دو) | `name` |
| `--files-only` | فقط فایل‌های منطبق با نام اصلی در پوشه‌ی خروجی ذخیره می‌شوند: بدون یادداشت، پیاده‌سازی و LLM. با `--summary`، `--taqrir` و `--reuse-transcripts` هم‌زمان نمی‌شود | خاموش |

الگوها regex پایتون و بدون حساسیت به حروف بزرگ و کوچک‌اند؛ یک کلمه‌ی ساده هم همان‌طور کار می‌کند. پیش از مقایسه، متن فارسی در دو طرف یکسان‌سازی می‌شود: ‏`ي/ك` به `ی/ک` تبدیل می‌شود، کشیده و اعراب حذف می‌شوند و نیم‌فاصله و `_` مثل فاصله‌اند؛ پس `--match "جزوه فقه"` فایل `جزوه_فقه.pdf` را هم پیدا می‌کند. فیلتر روی هر فایل جداگانه اعمال می‌شود: در آلبومی با یک PDF و یک عکس فقط PDF نگه داشته می‌شود. با `--since/--until`، `--limit`، `--types` و `--max-size` ترکیب می‌شود؛ برای پیش‌نمایش از `--dry-run` استفاده کنید (ستون *Files* فایل‌های منطبق را نشان می‌دهد).

حالت `--files-only` مانیفست جدا (`.versline-files.json`) دارد؛ پس اجرای دوباره پست‌های تمام‌شده را رد می‌کند و با آرشیو معمولی در همان پوشه تداخلی ندارد. فایلی که نام و حجمش با فایل موجود در پوشه یکی باشد تکراری حساب و رد می‌شود؛ همان نام با حجم متفاوت به شکل `name (post <id>).ext` ذخیره می‌شود. دانلود اسناد به حالت ورود با حساب نیاز دارد: با `--web` رد‌شده گزارش می‌شوند.

### خروجی

| گزینه | توضیح | پیش‌فرض |
| :--- | :--- | :--- |
| `-o, --output` | پوشه‌ی خروجی (به گنجینه‌ی خود اشاره دهید) | `output/<channel>` |
| `--keep-media` | رسانه را در `attachments/` ذخیره و در یادداشت جاسازی کن | خاموش |
| `--max-size MB` | رسانه‌ی بزرگ‌تر را رد کن (در `skipped_media` ثبت می‌شود) | نامحدود |
| `--no-transcribe` | فقط متن پست و فراداده | خاموش |

### پست‌های چندبخشی

مطالب بلند اغلب در چند پست پشت‌سرهم فرستاده می‌شوند. با `--merge-parts` چنین زنجیره‌ای **یک یادداشت** می‌شود.

| گزینه | توضیح | پیش‌فرض |
| :--- | :--- | :--- |
| `--merge-parts` | اگر فاصله‌ی دو پست از حد مجاز کمتر باشد و پست قبلی با نشانه‌ی ادامه تمام شود (`⬇️`، `👇`، `ادامه دارد`، `ادامه در پست بعد`) **یا** پست بعدی با نشانه‌ای شروع شود (`⬆️`، `👆`، `ادامه`، `ادامه‌ی پست قبل`)، پست در قبلی ادغام می‌شود | خاموش |
| `--merge-gap MIN` | بیشینه‌ی فاصله‌ی دقیقه‌ای بین بخش‌ها | ۱۵ |

سطرهای نشانه حذف و متن‌ها پشت هم می‌آیند؛ رسانه‌ی همه‌ی بخش‌ها به ترتیب نگه داشته (و پیاده) می‌شود. یادداشت به نام بخش اول است، فرانتمتر آن `post_ids` و `part_urls` دارد و پانوشت به همه‌ی بخش‌ها پیوند می‌دهد. در `.versline-channel.json` پست اول `parts: [...]` و بقیه `merged_into` می‌گیرند. بخش‌هایی که پیش‌تر جدا بایگانی شده‌اند در اجرای بعدیِ همراه این گزینه ادغام می‌شوند: یادداشت‌های قدیمی حذف و متن‌های پیاده‌شده بازاستفاده می‌شود، پس دوباره پیاده نمی‌شود. زنجیره‌ای که `--until` وسطش را ببرد در اجرای بعدی که کل زنجیره را شامل شود ادغام می‌شود. با `--files-only` نادیده گرفته می‌شود.

### بخش‌های اضافه (با LLM)

| گزینه | توضیح |
| :--- | :--- |
| `--summary` | بخش **خلاصه** را بالای یادداشت می‌افزاید (از متن پیاده‌شده یا متن پست)؛ برای محتوای کمتر از حدود ۳۰۰ نویسه رد می‌شود |
| `--taqrir` | بخش **تقریر و صورت‌بندی** را بعد از متن پیاده‌شده می‌افزاید: سخنرانی به یک شرح مکتوب ساخت‌یافته (مسئله، ادعاها، استدلال‌ها، اشکال‌ها، نتیجه) بازنویسی می‌شود، وفادار به گوینده. برای پست‌های متنی از متن پستِ حداقل حدود ۳۰۰ نویسه با پرامپتی مناسب متن مکتوب ساخته می‌شود |
| `--output-lang` | زبان خلاصه/تقریر (پیش‌فرض: همان زبان محتوا) |

پرامپت‌ها در `src/versline/resources/prompts/` هستند (`channel_summary_prompt.md`، `channel_taqrir_prompt.md`، `channel_taqrir_text_prompt.md`). هزینه‌ها در گزارش پایانی می‌آید؛ در کانال‌های بزرگ ابتدا با `--limit 3` امتحان کنید.

### ادامه دادن و تکرار

- اجرای دوباره، پست‌های بایگانی‌شده را رد می‌کند (فایل `.versline-channel.json`). پستی که خطا بدهد «ناموفق» ثبت و در اجرای بعد دوباره تلاش می‌شود، بدون اینکه بقیه متوقف شوند. Ctrl+C امن است (کد خروج ۱۳۰)؛ همان دستور را دوباره اجرا کنید تا ادامه یابد.
- `-f, --force`: پست‌ها از صفر، از جمله پیاده‌سازی، دوباره پردازش می‌شوند.
- `--reuse-transcripts`: متن پست، عنوان، برچسب‌ها، `--summary` و `--taqrir` دوباره ساخته می‌شوند ولی متن پیاده‌شده‌ی موجود در هر یادداشت حفظ می‌شود (بدون دانلود و بدون هزینه‌ی پیاده‌سازی جدید). پستِ بدون متن ذخیره‌شده عادی پیاده می‌شود. بر `--force` غلبه دارد. ویرایش‌های شما در متن پیاده‌شده حفظ می‌شود؛ ویرایش در بخش‌های دیگر یادداشت بازنویسی می‌شود.

### بازنویسی تنظیمات LLM و پیاده‌سازی

`--model`، `--provider`، `--api-key`، `--api-endpoint`، `--proxy` (برای LLM)، `--telegram-proxy`، `--extra-body`، `--note`/`--note-file` (به پرامپت پیاده‌سازی اضافه می‌شود)، `--chunk-size 900`، `--overlap 180`، `--skip-blocked`.

## چه چیزی نوشته می‌شود

```text
<out>/
├── <عنوان کانال>.md                    # فهرست: جدول پست‌های بایگانی‌شده
├── .versline-channel.json             # فایل وضعیت برای ادامه
├── posts/
│   └── 2026-03-14 - 223 - <title>.md  # یک یادداشت برای هر پست
└── attachments/                       # فقط با --keep-media
```

هر یادداشت: فرادادهی بالای فایل، `# عنوان` (اولین خط معنادار متن پست بدون هشتگ/لینک/Markdown، حداکثر ۸۰ نویسه؛ در نبود آن `پست <id>`)، **خلاصه**، **توضیحات** (متن پست)، **متن پیاده‌شده** (آلبوم‌ها به `### 1`، `### 2` تقسیم می‌شوند)، **تقریر و صورت‌بندی**، **پیوست‌ها** (جاسازی `![[...]]`) و در پایان پیوند به پست اصلی.

فرادادهی همیشگی: `title, source, channel, channel_title, post_id, url, date, date_shamsi, media_type, tags, aliases, archived_at`؛ در صورت وجود: `duration, file_name, views, forwards, forwarded_from, album_size, transcribed, transcription_model, summary_model, taqrir_model, skipped_media`. هشتگ‌ها به `tags` تبدیل می‌شوند (نیم‌فاصله یا فاصله داخل هشتگ به `_` بدل می‌شود؛ `telegram` همیشه اضافه است). یادداشت فهرست شامل `type: channel-index`، `post_count`، `range_from`، `range_to`، `updated` و جدولی از پیوندهای داخلی است. حرف‌های اضافه‌ی مدل مثل شروع «بله، حتماً…» یا پایان «[---پایان فایل صوتی---]» از متن حذف می‌شود.

## بسته‌ی کامل و مرتب

`versline telegram pack پوشه_آرشیو` یک آرشیو تمام‌شده را بدون اتصال به اینترنت به یک بسته‌ی قابل‌اشتراک تبدیل می‌کند (چیزی دوباره دانلود نمی‌شود). نیاز به `versline[export]` دارد.

```text
<output>/<channel>_pack/<channel>_<from>_<to>/
├── README.md, README.pdf            کانال، بازه‌ی زمانی، تعداد پست، مجموع مدت صوت، محتوای بسته
├── <عنوان کانال>.docx / .pdf        «کتاب»: جلد، فهرست مطالب، فصل‌بندی بر اساس ماه شمسی، هر پست در صفحه‌ی جدید
├── posts/docx/…  posts/pdf/…        برای هر پست یک فایل Word و یک PDF
├── notes/                           یادداشت‌های Markdown و فهرست (قابل‌باز در Obsidian)، با پیوست‌ها
├── catalog.csv, catalog.xlsx        هر پست یک ردیف: تاریخ، عنوان، نوع، مدت، بازدید، پیوند، مسیر یادداشت/Word/PDF، پیوست‌ها
<output>/<channel>_pack/<channel>_<from>_<to>.zip   همه‌ی موارد بالا در یک فایل
```

| گزینه | معنی |
| :--- | :--- |
| `--output`، `-o` | پوشه‌ای که بسته در آن ساخته می‌شود |
| `--to docx,pdf` | قالب کتاب و فایل‌های تک‌پست |
| `--front-matter` / `--no-front-matter` | جدول مشخصات زیر جلد و عنوان هر پست |
| `--per-post` / `--no-per-post` | یک فایل برای هر پست (پیش‌فرض: روشن) |
| `--media` / `--no-media` | کپی پیوست‌ها در `notes/` (پیش‌فرض: روشن) |
| `--toc` / `--no-toc` | فهرست مطالب در کتاب: لینک‌های قابل‌کلیک، گروه‌بندی‌شده بر اساس ماه شمسی (پیش‌فرض: روشن) |
| `--zip` / `--no-zip` | ساخت ZIP (پیش‌فرض: روشن) |
| `--since`، `--until` | محدود کردن به بازه‌ی تاریخ (میلادی یا شمسی) |
| `--force`، `-f` | ساخت دوباره‌ی فایل‌های تک‌پستِ به‌روز |

پست‌های چندبخشیِ ادغام‌شده یک بار می‌آیند. اجرای دوباره ارزان است: فایل‌های تک‌پستِ به‌روز رد می‌شوند و کتاب، فهرست، README و ZIP دوباره ساخته می‌شوند.

در `archive` می‌شود یک‌جا انجام داد: `--pack` بعد از بایگانی بسته‌ی کامل را می‌سازد و `--export docx,pdf` فقط فایل‌های تک‌پست را در `<output>/exports/` می‌نویسد.

## تقریر مباحثات یک گفتگو: `telegram taqrir`

`versline telegram taqrir گفتگو --since … --until …` همه‌ی پیام‌های یک گفتگو (چت خصوصی، گروه، سوپرگروه یا کانال) را در یک بازه‌ی زمانی می‌خواند و **برای کل بازه یک یادداشت تقریر** می‌نویسد. مناسب گروه‌های مباحثه و بحث‌های علمی که با پیام صوتی، متن، PDF و عکس صفحه‌ی کتاب پیش می‌روند.

- **پیام صوتی، فایل صوتی و ویدیو** پیاده می‌شوند (با همان موتور و حافظه‌ی `archive`).
- **اسناد** (pdf، docx، pptx، xlsx، html، txt، md و…) به متن خوانده می‌شوند؛ از هر سند حداکثر `--doc-chars` نویسه (پیش‌فرض ۳۰۰۰۰).
- **عکس‌ها** با مدل بینایی خوانده می‌شوند (صفحه‌ی کتاب، دست‌نوشته، اسکرین‌شات، جدول)؛ با `--no-images` خاموش می‌شود.
- پاسخ‌ها («در پاسخ به #id») و بازنشرها حفظ می‌شوند تا مدل بفهمد چه کسی به چه کسی جواب داده است.

```sh
# پیدا کردن گفتگو (چت خصوصی و گروه معمولی نام کاربری ندارند)
versline telegram chats --search "مباحثه"

# پیش‌نمایش بازه: پیام‌ها، فرستنده‌ها، رسانه‌ها (بدون دانلود و بدون LLM)
versline telegram taqrir @study_group --since 1404-07-01 --until 1404-07-15 --dry-run

# تقریر + ادعاها و ادله در یک یادداشت، در گنجینه‌ی Obsidian
versline telegram taqrir @study_group --since 1404-07-01 --until 1404-07-15 -o ~/Vault/تقریرات

# گفتگو با شناسه‌ی عددی (شناسه‌ای را که با - شروع می‌شود بعد از -- بنویسید)
versline telegram taqrir --since 1404-07-01 --style claims -- -1001234567890
```

### انواع تقریر

| `--style` | بخش | چیست |
| :--- | :--- | :--- |
| `descriptive` | **تقریر** | نثر علمی، برای هر موضوع یک `###`: محل بحث، دیدگاه‌ها با صورت‌بندی استدلال‌ها، ادله، اشکال و پاسخ، نتیجه |
| `claims` | **ادعاها و ادله** | هر محل نزاع (`محل بحث`) با گزاره‌هایش به صورت بالت‌پوینت‌های دقیق و تک‌مدعایی (`گزاره ۱.۱`) و زیر هر گزاره ادله (`دلیل`)، اشکال‌ها (`اشکال`) و پاسخ‌ها (`پاسخ`)؛ گزاره‌ی بی‌دلیل علامت می‌خورد |
| `both` (پیش‌فرض) | هر دو | هر دو بخش در یک یادداشت |

هر نکته به پیام‌هایش ارجاع می‌دهد: `[#123]` به پیوند پیام در t.me (کانال و سوپرگروه) یا به همان پیام در یادداشت متن گفتگو (چت خصوصی و گروه معمولی) تبدیل می‌شود.

### نام شرکت‌کنندگان

به‌طور پیش‌فرض **بی‌نام** است: در متنی که مدل می‌بیند، افراد «شرکت‌کننده ۱»، «شرکت‌کننده ۲»… نامیده می‌شوند (برای هر نفر ثابت) و تقریر همین برچسب‌ها یا تعبیرهای غیرشخصی را به کار می‌برد. با `--attribute` نام واقعی افراد می‌آید و فهرستشان در فراداده (`participants`) ثبت می‌شود.

### خروجی

در `output/<گفتگو>/taqrir/` (یا مسیر `-o`):

- `<از> تا <تا> - تقریر.md`: فراداده (`type: chat-taqrir`، گفتگو، تاریخ میلادی و شمسی، تعداد پیام‌ها، شرکت‌کنندگان، تعداد صوت و سند و تصویرِ خوانده‌شده، نوع تقریر، مدل)، بخش‌ها، **منابع** (اسناد به‌اشتراک‌گذاشته) و پیوند به متن گفتگو.
- `<از> تا <تا> - متن کامل گفتگو.md`: متن کامل پیام‌ها به تفکیک روز: سرتیتر (شناسه، ساعت، شرکت‌کننده، پاسخ)، متن، متن پیاده‌شده‌ی صوت‌ها، و متن سند و تصویر در کادرهای جمع‌شونده. هر پیام شناسه‌ی بلوک (`^m123`) دارد تا ارجاع‌ها مستقیم به آن بروند. `--no-log` این فایل را نمی‌سازد.
- `-X docx,pdf` یادداشت تقریر را به Word/PDF هم می‌برد.

### گفتگوهای طولانی، حافظه و ادامه

متن پیاده‌شده، متن اسناد و متن تصاویر بعد از هر پیام در `.versline-taqrir.json` در پوشه‌ی خروجی ذخیره می‌شود: اجرای قطع‌شده از همان‌جا ادامه می‌یابد و اجرای دوباره (مثلاً با `--style` دیگر) چیزی را دوباره نمی‌خواند. فایلی که خوانده نشود گزارش و در اجرای بعد دوباره امتحان می‌شود و تقریر را متوقف نمی‌کند.

اگر متن گفتگو از `--max-chars` (پیش‌فرض ۱۵۰۰۰۰) بلندتر باشد، در مرز روزها (یا پیام‌ها) به چند بخش تقسیم می‌شود. مدل ابتدا از هر بخش یادداشت ساختاریافته برمی‌دارد (این هم ذخیره می‌شود) و سپس هر نوع تقریر را از مجموع یادداشت‌ها می‌نویسد؛ بنابراین اجرای دوباره با نوع دیگر فقط یک فراخوانی به ازای هر نوع هزینه دارد. `--force` حافظه را نادیده می‌گیرد.

### گزینه‌ها

| گزینه | معنی |
| :--- | :--- |
| `--since`، `--until` | بازه‌ی تاریخ (میلادی یا شمسی، با `HH:MM` اختیاری) |
| `--style` | `descriptive`، `claims` یا `both` |
| `--attribute` | آوردن نام شرکت‌کنندگان |
| `--no-transcribe`، `--no-documents`، `--no-images` | آن نوع رسانه خوانده نشود (فقط علامتش می‌ماند) |
| `--types`، `--limit` | فقط برخی انواع پیام / حداکثر N پیام |
| `--output-lang` | زبان تقریر (پیش‌فرض: زبان خود بحث) |
| `--instruction`، `--instruction-file` | راهنمای اضافه برای تقریر، مثلاً «فقط بحث دلالت امر بر وجوب» |
| `--note`، `--note-file` | دستور اضافه برای پرامپت پیاده‌سازی (مثل `archive`) |
| `--doc-chars`، `--max-chars`، `--max-size` | سقف هر سند، اندازه‌ی هر بخش در گفتگوهای طولانی، رد رسانه‌ی بزرگ‌تر از N مگابایت |
| `--no-log`، `--dry-run`، `--force` | توضیح در بالا |
| `-X`، `--export-frontmatter` | خروجی Word/PDF |

گزینه‌های LLM (`--model`، `--provider`، `--api-key`، `--api-endpoint`، `--proxy`، `--telegram-proxy`، `--extra-body`، `--chunk-size`، `--overlap`، `--skip-blocked`) مثل `archive` کار می‌کنند. خواندن عکس به مدل چندوجهی نیاز دارد (همه‌ی مدل‌های Gemini، مدل‌های هم‌رده‌ی gpt-4o). ورود به حساب لازم است (`telegram login`)؛ `--web` اینجا در دسترس نیست.

## نمونه‌ها

```sh
# کانال صوتی: متن پیاده‌شده + خلاصه + تقریر، با نگه‌داشتن رسانه
versline telegram archive @lectures --since 1404-07-01 --summary --taqrir --keep-media -o ~/Vault/Telegram/lectures

# کانال عمومی فقط‌متنی، بدون ورود
versline telegram archive @news --web --types text --summary --taqrir

# افزودن خلاصه/تقریر به پست‌های بایگانی‌شده بدون پیاده‌سازی دوباره
versline telegram archive @lectures --since 1404-07-01 --summary --taqrir --reuse-transcripts -o ~/Vault/Telegram/lectures

# فقط فایل‌های PDF/Word که نامشان «جزوه» دارد ولی «پیش‌نویس» یا «draft» ندارد
versline telegram archive @chan --files-only --ext pdf,word --match "جزوه" --exclude "پیش‌نویس|draft" -o ~/Downloads/chan

# پیش‌نمایش PDFهایی که نام یا متن پستشان «جلسه <عدد>» دارد
versline telegram archive @chan --files-only --ext pdf --match 'جلسه\s*\d+' --match-in any --dry-run

# فقط محتوای گفتاری، رد فایل‌های بالای ۲۰۰ مگابایت، خلاصه‌ی انگلیسی
versline telegram archive @lectures --types audio,voice,video --max-size 200 --summary --output-lang English
```
