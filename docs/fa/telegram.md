# بایگانی کانال تلگرام

[فهرست](index.md) · [English](../en/telegram.md) · **فارسی**

یک کانال تلگرام را در قالب یک گنجینه‌ی Obsidian بایگانی کنید: **برای هر پست یک یادداشت Markdown** (متن پست، متن پیاده‌شده‌ی صوت/ویدیو، خلاصه و *تقریر* اختیاری، فرادادهی کامل) به‌علاوه‌ی یک یادداشت فهرست کانال. برای کانال‌های صوتی/تصویری، فقط‌متنی و ترکیبی کار می‌کند.

## شروع سریع

```sh
# ۱. یک بار وارد شوید (برای کانال‌های عمومی می‌توانید این مرحله را رد کنید و از --web استفاده کنید)
versline telegram login

# ۲. پیش‌نمایش یک بازه‌ی زمانی (چیزی دانلود یا نوشته نمی‌شود)
versline telegram archive @channel --since 2026-03-01 --until 2026-03-31 --dry-run

# ۳. بایگانی در گنجینه‌ی خود
versline telegram archive @channel --since 2026-03-01 --until 2026-03-31 -o ~/Vault/Telegram/channel
```

تنظیمات LLM از `VERSLINE_LLM_*` / `versline init` یا گزینه‌های زیر گرفته می‌شود. پیاده‌سازی متن به یک سرویس LLM نیاز دارد؛ ffmpeg همراه برنامه است.

## دو روش اتصال

| | ورود با حساب (پیش‌فرض) | پیش‌نمایش وب (`--web`) |
| :--- | :--- | :--- |
| نیاز به `api_id`/`api_hash` و `telegram login` | بله | **خیر** |
| کانال‌ها | عمومی، خصوصی، و عضوشده با لینک دعوت | **فقط عمومی** (`@name`، `t.me/name`) |
| فایل صوتی، سند، ویدیوی حجیم | دانلود و پیاده‌سازی می‌شود | **قابل دانلود نیست**: برای پست یادداشت ساخته می‌شود و مورد در `skipped_media` با عبارت «<نوع> not downloadable» ثبت می‌شود |
| پیام صوتی، ویدیوی گرد، ویدیوی کوچک | بله | بله |
| سرعت | سریع | کندتر (فاصله‌ی ۰٫۴ ثانیه بین درخواست‌ها و عقب‌نشینی در خطای HTTP 429)؛ بازه‌ی زمانی با جست‌وجوی دودویی پیدا می‌شود |

**حالت ورود با حساب.** `api_id` و `api_hash` را از <https://my.telegram.org> بخش *API development tools* بگیرید. آن‌ها را در env بگذارید (`VERSLINE_TELEGRAM_API_ID`، `VERSLINE_TELEGRAM_API_HASH`) یا بگذارید `versline telegram login` بپرسد و ذخیره کند. ورود، شماره‌ی تلفن، کد و (در صورت فعال بودن) رمز دومرحله‌ای را می‌خواهد. تنظیم متغیرها به‌تنهایی ورود **نیست**. فایل نشست (در پوشه‌ی تنظیمات یا `VERSLINE_TELEGRAM_SESSION_PATH`) به حساب شما دسترسی می‌دهد؛ آن را محرمانه نگه دارید. `versline telegram logout` نشست را پایان می‌دهد و فایل را حذف می‌کند.

**حالت وب.** `--web` آدرس `https://t.me/s/<channel>` را می‌خواند؛ کانال خصوصی، لینک دعوت و `t.me/c/...` رد می‌شوند. کانال ناموجود یا بدون پیش‌نمایش، خطای «پیدا نشد» می‌دهد.

**پروکسی.** برای تلگرام ترتیب این است: `--telegram-proxy` ← `VERSLINE_TELEGRAM_PROXY` ← `--proxy`/`VERSLINE_LLM_PROXY`. پروتکل‌ها: `socks5`، `socks5h`، `socks4`، `http`، `https`. در `archive`، گزینه‌ی `--proxy` برای سرویس LLM است.

## `telegram login` / `logout`

```sh
versline telegram login [--proxy URL]
versline telegram logout
```

## `telegram archive`

```sh
versline telegram archive [OPTIONS] CHANNEL
```

`CHANNEL`: ‏`@name`، `name`، `https://t.me/name`، `t.me/s/name`، `https://t.me/c/<id>` (خصوصی) یا لینک دعوت کانالی که قبلاً عضوش شده‌اید (دو مورد آخر فقط در حالت ورود با حساب).

### انتخاب پست‌ها

| گزینه | توضیح | پیش‌فرض |
| :--- | :--- | :--- |
| `--since`، `--until` | ‏`YYYY-MM-DD[ HH:MM]` میلادی یا شمسی (`1404-07-01`؛ سال کمتر از ۱۷۰۰ شمسی است؛ ارقام فارسی و `/` پذیرفته می‌شود). تاریخ بدون ساعت کل روز را شامل می‌شود؛ `--until` شامل خودش است. | کل کانال |
| `--limit N` | حداکثر N پست منطبق | نامحدود |
| `--types` | فهرست جداشده با ویرگول از `audio,voice,video,video_note,photo,document,text` | همه |
| `--dry-run` | جدول پست‌های منطبق (شناسه، تاریخ، نوع، مدت، عنوان) بدون نوشتن چیزی | خاموش |

نوع هر پست برابر نوع **اولین** رسانه‌ی آن است (آلبومی که با عکس شروع شود = `photo`)؛ بدون رسانه = `text`. فقط voice، audio، video و video_note پیاده‌سازی می‌شوند؛ بقیه فقط متن پست و فراداده می‌گیرند.

### خروجی

| گزینه | توضیح | پیش‌فرض |
| :--- | :--- | :--- |
| `-o, --output` | پوشه‌ی خروجی (به گنجینه‌ی خود اشاره دهید) | `output/<channel>` |
| `--keep-media` | رسانه را در `attachments/` ذخیره و در یادداشت جاسازی کن | خاموش |
| `--max-size MB` | رسانه‌ی بزرگ‌تر را رد کن (در `skipped_media` ثبت می‌شود) | نامحدود |
| `--no-transcribe` | فقط متن پست و فراداده | خاموش |

### بخش‌های اضافه (با LLM)

| گزینه | توضیح |
| :--- | :--- |
| `--summary` | بخش **خلاصه** را بالای یادداشت می‌افزاید (از متن پیاده‌شده یا متن پست)؛ برای محتوای کمتر از حدود ۳۰۰ نویسه رد می‌شود |
| `--taqrir` | بخش **تقریر و صورت‌بندی** را بعد از متن پیاده‌شده می‌افزاید: سخنرانی به یک شرح مکتوب ساخت‌یافته (مسئله، ادعاها، استدلال‌ها، اشکال‌ها، نتیجه) بازنویسی می‌شود، وفادار به گوینده. برای پست‌های متنی از متن پستِ حداقل حدود ۳۰۰ نویسه با پرامپتی مناسب متن مکتوب ساخته می‌شود |
| `--output-lang` | زبان خلاصه/تقریر (پیش‌فرض: همان زبان محتوا) |

پرامپت‌ها در `src/versline/resources/prompts/` هستند (`channel_summary_prompt.md`، `channel_taqrir_prompt.md`، `channel_taqrir_text_prompt.md`). هزینه‌ها در گزارش پایانی می‌آید؛ در کانال‌های بزرگ ابتدا با `--limit 3` امتحان کنید.

### ادامه دادن و تکرار

- اجرای دوباره، پست‌های بایگانی‌شده را رد می‌کند (فایل `.versline-channel.json`). پستی که خطا بدهد «ناموفق» ثبت و در اجرای بعد دوباره تلاش می‌شود، بدون اینکه بقیه متوقف شوند. Ctrl+C امن است (کد خروج ۱۳۰)؛ همان دستور را دوباره اجرا کنید تا ادامه یابد.
- `-f, --force`: پست‌ها از صفر، از جمله پیاده‌سازی، دوباره پردازش می‌شوند.
- `--reuse-transcripts`: متن پست، عنوان، برچسب‌ها، `--summary` و `--taqrir` دوباره ساخته می‌شوند ولی متن پیاده‌شده‌ی موجود در هر یادداشت حفظ می‌شود (بدون دانلود و بدون هزینه‌ی پیاده‌سازی جدید). پستِ بدون متن ذخیره‌شده عادی پیاده می‌شود. بر `--force` غلبه دارد. ویرایش‌های شما در متن پیاده‌شده حفظ می‌شود؛ ویرایش در بخش‌های دیگر یادداشت بازنویسی می‌شود.

### بازنویسی تنظیمات LLM و پیاده‌سازی

`--model`، `--provider`، `--api-key`، `--api-endpoint`، `--proxy` (برای LLM)، `--telegram-proxy`، `--extra-body`، `--note`/`--note-file` (به پرامپت پیاده‌سازی اضافه می‌شود)، `--chunk-size 900`، `--overlap 180`، `--skip-blocked`.

## چه چیزی نوشته می‌شود

```text
<out>/
├── <عنوان کانال>.md                    # فهرست: جدول پست‌های بایگانی‌شده
├── .versline-channel.json             # فایل وضعیت برای ادامه
├── posts/
│   └── 2026-03-14 - 223 - <title>.md  # یک یادداشت برای هر پست
└── attachments/                       # فقط با --keep-media
```

هر یادداشت: فرادادهی بالای فایل، `# عنوان` (اولین خط معنادار متن پست بدون هشتگ/لینک/Markdown، حداکثر ۸۰ نویسه؛ در نبود آن `پست <id>`)، **خلاصه**، **توضیحات** (متن پست)، **متن پیاده‌شده** (آلبوم‌ها به `### 1`، `### 2` تقسیم می‌شوند)، **تقریر و صورت‌بندی**، **پیوست‌ها** (جاسازی `![[...]]`) و در پایان پیوند به پست اصلی.

فرادادهی همیشگی: `title, source, channel, channel_title, post_id, url, date, date_shamsi, media_type, tags, aliases, archived_at`؛ در صورت وجود: `duration, file_name, views, forwards, forwarded_from, album_size, transcribed, transcription_model, summary_model, taqrir_model, skipped_media`. هشتگ‌ها به `tags` تبدیل می‌شوند (نیم‌فاصله یا فاصله داخل هشتگ به `_` بدل می‌شود؛ `telegram` همیشه اضافه است). یادداشت فهرست شامل `type: channel-index`، `post_count`، `range_from`، `range_to`، `updated` و جدولی از پیوندهای داخلی است. حرف‌های اضافه‌ی مدل مثل شروع «بله، حتماً…» یا پایان «[---پایان فایل صوتی---]» از متن حذف می‌شود.

## نمونه‌ها

```sh
# کانال صوتی: متن پیاده‌شده + خلاصه + تقریر، با نگه‌داشتن رسانه
versline telegram archive @lectures --since 1404-07-01 --summary --taqrir --keep-media -o ~/Vault/Telegram/lectures

# کانال عمومی فقط‌متنی، بدون ورود
versline telegram archive @news --web --types text --summary --taqrir

# افزودن خلاصه/تقریر به پست‌های بایگانی‌شده بدون پیاده‌سازی دوباره
versline telegram archive @lectures --since 1404-07-01 --summary --taqrir --reuse-transcripts -o ~/Vault/Telegram/lectures

# فقط محتوای گفتاری، رد فایل‌های بالای ۲۰۰ مگابایت، خلاصه‌ی انگلیسی
versline telegram archive @lectures --types audio,voice,video --max-size 200 --summary --output-lang English
```

همچنین [رفع اشکال](troubleshooting.md#telegram) را ببینید.
